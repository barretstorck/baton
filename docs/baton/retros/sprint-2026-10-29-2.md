## What went wrong

| Problem | Cost | Root cause |
|---|---|---|
| Reviewers approved PRs whose security weaknesses the orchestrator had already noted on the issue (#139 bypass gaps, #151 approval TOCTOU, #156 marker spoofing, #171 probe spoofing, #172 hand-off marker) | Six security follow-ups filed after merge (#193, #198, #201, #204, #214 and #179 in part) | The reviewer weighs the issue's acceptance criteria. Orchestrator `status` notes are not criteria, so out-of-scope security gaps become follow-ups instead of fix tasks. The automated review findings arrived after the plan was written. |
| `baton pr create` refuses a detached HEAD | Every task-1 developer (about 20) worked around it by creating a local branch | The develop skill checks out detached, but `pr create` needs a named branch |
| Merged PRs conflicted with later PRs on shared files (`tests/test_template.py`, `skills/sprint/SKILL.md`, `lib/baton/cli.py`) | 5 update dispatches (#191 twice, #206, #209, #211) and 3 re-reviews of stale approvals | Many issues append to the same test and skill files; the file-overlap check only looks at plan Expected files |
| The stale-plan check held #163 over `cli.py` and `file::test` tokens | One extra refiner dispatch | The refiner wrote bare names and pytest-style ids; #174 fixed bare names without an extension but not these forms |
| `merge-pr` printed "cleanup skipped: remote ref does not exist" on every merge | None (GitHub had already deleted the branch) | The repository deletes head branches on merge; `merge-pr` treats the missing ref as a failure |
| The orchestrator session ran long (80% of its calls above 250K context) | 13.5M weighted tokens, more than half the sprint's total | 32 issues and about 160 agent results in one session; no fresh session was started |

## How to improve

1. **Baton itself:** `baton pr create` should accept a detached HEAD by taking `--head <branch>` from the pushed ref, or the develop skill should check out a named branch for task 1.
2. **Baton itself:** the review skill should treat orchestrator `status` notes that name a security weakness in the changed code as review input: fix it in the PR or file a ranked follow-up, and say which in the review.
3. **Baton itself:** `merge-pr` should treat "remote ref does not exist" after a merge as success, not "cleanup skipped".
4. **Baton itself:** the sprint skill should recommend a fresh orchestrator session after about 15 merges, so the session stays under 250K.
5. **This repository (issue):** the stale-plan check should accept `path::test` tokens and resolve bare file names against the tree (a follow-up to #174).
