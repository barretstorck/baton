## What went right

- All 11 issues, stretch included, landed in one day with no question to the maintainer and no blocked issue.
- Small tasks kept every developer and reviewer under 110K tokens at peak; none crossed 250K.
- Review caught real problems: an automated security review flagged that `_settle` trusted any linked run, and round 1 on #27 made it check the head sha and workflow name. Round 1 on #34 found `pr-state` missing `headRefOid`, and on #37 found `references/github.md` out of date.
- Developers reported partial overlaps honestly (task 1 of #19 already held task 2's wording), so the next task verified instead of duplicating.
- `sprint-status`'s overlap and blocker holds kept the two slots from colliding; trial merges before each last task found no conflicts.

## How to improve

1. **Baton itself (release):** cut a release with this sprint's fixes and update the plugin everywhere it is installed. Until then, sessions keep the 0.4.0 behaviour that stalled #34, and the sprint skill still lacks #16 and #19. A Baton sprint could also run `bin/baton` from the default branch instead of the installed copy.
2. **Baton itself (issue):** capture stdout in the `tests/test_checklist.py` tick tests, so the suite stops printing `ticked in docs/baton/plans/7-x.md`.
3. **Baton itself (issue):** let developers and reviewers create scratch git repositories under their worktree or the scratchpad, or ship a small live-git test harness CI can run, so plumbing like `planfile.write` is checked before review.
4. **Baton itself (sprint skill):** suggest a fresh orchestrator session after a set number of merges, or when the orchestrator's peak passes 250K, before the context gets large.
5. **Baton itself (issue):** `merge-pr` should skip the local branch cleanup silently when the branch never existed locally.
6. **Baton itself (issue, from the review of #31):** `triggers_on_push` treats any `push` key as a trigger, so a workflow filtered to other branches or paths can show `pending` for up to the 5-minute grace period. Worth reading `branches`/`paths` if it shows up in practice.
7. **This repository's brief:** no change needed.
