## What went right

- Both spikes (#361, #362) ended with a usable split: 19 child issues, all delivered inside the same sprint, so Forgejo and GitLab now each have a backend, detection, merge-pr semantics, identity, gate rules and README setup.
- With one developer slot, 202 plan tasks ran one at a time with no task agent over 51K tokens peak; reviewers and refiners running alongside kept the slot busy.
- Reviews caught real defects before merge (20 pull requests sent back), including `--` and `clean` bypasses in the Forgejo gate rule (#416) and a test class defined twice that silently hid tests (#426).
- The follow-up rule in the milestone description made every sprint decision about follow-ups mechanical; no follow-up needed a separate maintainer call.

## How to improve

Each item names where the change belongs: this repository's brief, an issue, or Baton itself.

1. Baton itself: before dispatching, `baton sprint-status` (or the orchestrator) checks that the session's cwd is a git work tree and says so plainly, instead of every Agent call failing.
2. Baton itself: cut the parent's share of the quota. The parent should relay only the first line of an agent's return and let the orchestrator read the rest from the forge, or compact sooner.
3. Baton itself: the refiner marks facts about external CLIs and unread code in Design notes as unverified, and the developer brief says to check them or report them as unchecked (seen on #416 and #382).
4. Baton itself: `baton config` prints the detected forge (noted while refining #422).
5. This repository's brief: `.baton/brief.md` still names `references/github.md`; after #422 it should name the forge-neutral references set. `.baton/` is protected, so the maintainer makes this edit.
6. This repository's brief: when a sprint is expected to touch `lib/baton/gate.py`, say so in the milestone so the maintainer plans to be present for `/baton approve`.
