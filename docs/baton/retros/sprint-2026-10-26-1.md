## What went right

- Every issue was finished, including all five stretch issues, in one sitting.
- No agent conversation grew past 250K tokens. The largest developer task peaked at 104K (#49) and the largest reviewer at 43K (#51). One-task-per-agent kept every developer small.
- Thirteen of seventeen pull requests were approved on the first review. The four that needed a second round (#69, #82, #84, #87) each settled in one round of fixes; none escalated.
- Reviewers caught real defects. These included `baton clean` force-removing worktrees locked by live processes (#69), and an incomplete renumbering of task references in `plan insert` (#84). On #87, the reviewer reproduced two of three security findings before asking for fixes.
- Developers flagged their own gaps honestly: a bug from task 4 of #49, an untested CLI wiring in #53, and a skipped brief sentence in #63.

## What went wrong

| Problem | Cost | Root cause |
|---|---|---|
| The orchestrator session was the largest consumer | 17.6M weighted (52% of the sprint), peak 452K, 73% of its calls above 250K | The whole 17-issue sprint ran in one orchestrator session. Every developer and reviewer report and every `sprint-status` read stayed in its context. The skill says to suggest a fresh session when context grows; this was offered once but not acted on. |
| Agent-built safety checks had bypasses that the reviewer did not find on its own | #87 needed a second review round with 3 fix tasks; #65's gap became follow-up #79 | The plans for #65 (gate) and #51 (forbid) listed the behaviour to add but no bypass cases to test: `gh api` for close/reopen; branch-name trust, `splitlines()` and quoted paths for forbid. An automated security review found them after the code was pushed. |
| `merge-pr` printed "cleanup skipped: branch not found" on every merge | Noise on 17 merges | The sprint ran the installed Baton 0.4.0, not the repository's code, so #57's fix did not apply to its own sprint. |
| Two pull requests were merged outside `merge-pr` | Plan pinning, label removal, status and branch deletion for #65 and #51 had to be done by hand | The maintainer merged #78 and #87 directly instead of commenting `/baton approve <sha>`. `merge-pr` has no path for a pull request that is already merged by someone else. |
| One free slot was left empty on purpose | A short idle gap while #77 was reviewed | `sprint-status` offered stretch #51 while deliverables #65 and #62 were held for file overlap. Starting #51 would have blocked both for six tasks. |
| A test fixture's stdout ("ticked in docs/baton/plans/7-x.md") confused developers | Mentioned in five developer reports | A test in `tests/test_checklist.py` lets `baton task done` output reach stdout during the suite. |

## How to improve

1. **Baton:** the orchestrator should hand over to a fresh `/baton:sprint` session on its own after a set number of passes or merges, not only suggest it. All state is on the forge, so nothing is lost, and this sprint shows the orchestrator dominates quota once it runs long.
2. **Baton (refine skill):** when an issue adds or changes a safety check (gate, hooks, `merge-pr` refusals), the plan should list the bypass cases to test: alternate commands, input that bends parsing, and identity taken from names an agent controls.
3. **Baton:** `merge-pr` on a pull request someone else already merged should run the post-merge steps (pin the plan link, set status, remove the branch and logs) instead of refusing. That would cover a maintainer merging directly after approving.
4. **Issue (to file if wanted):** stop the `tests/test_checklist.py` fixture from printing `baton task done` output during the suite.
5. **Maintainer:** update the installed Baton plugin to this release, so the next sprint runs with #49, #57, #62 and #63 in effect.
6. **Follow-ups to prioritise:** #74 (CLI cleanup test uses a copy of the guard), #79 (gate: close/reopen through `gh api`), #86 (stale-path check silent on a failed listing), #88 (pre-push hook trusts the pushed ref name; blocked until #51, which is now merged).
