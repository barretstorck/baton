## What went wrong

| Problem | Cost | Root cause |
|---|---|---|
| The orchestrator run ended as soon as developers were dispatched in the background | The maintainer had to resume the sprint by hand many times | The orchestrator handed back while agents were still running (fixed by #326) |
| Several PRs (#324, #333, #337) conflicted with main after other merges | An extra update developer and a re-review each | Many PRs touched the same reference files in parallel |
| `baton notify` allows one approval request per issue, so a moved head could not be re-requested | A status comment instead of a notification for #313 | The notify rule is once per issue and kind |
| PR #333 was reviewed twice | One wasted reviewer | The first reviewer's report arrived late, after a second was dispatched |

## How to improve

1. Baton: let a changed head re-request a protected-path approval (an issue for the maintainer to file).
2. Baton: order or batch PRs that edit the same reference files, so fewer need an update developer after a sibling merges.
3. Baton: wait for a reviewer's return before dispatching a second one for the same PR.
