## What went right

- Small tasks kept every agent small: no agent went past 96K tokens.
- Plans moved into the issue body and the `refs/plans` mechanism was removed in the same sprint, with the migrate path kept for old issues.
- Review caught a real trust-boundary weakness in #129 before merge.

## What went wrong

| Problem | Cost | Root cause |
|---|---|---|
| #127 stayed held after the first re-refinement | One extra refiner run | Line suffixes such as `file.py:~325` and a bare `refs/plans` in task text were read by the stale-plan check as missing paths |
| #127 task 5 returned a placeholder sha and its search missed #114, which still linked a plan ref | The orchestrator migrated #114 by hand | A no-code check task has no commit to report, and the developer's `gh` search matched the wrong text |
| #127 task 6 had to stop and ask | One round trip with the maintainer | The plan put an irreversible ref deletion inside the pull request's tasks |
| #129 needed two review rounds for `forbid.plan_text` | Two fix tasks | Moving allowances to the issue body widened who can set them; the first fix left unterminated comments and fences |
| `merge-pr` printed a cleanup error after merging #128 | None (merge succeeded) | The branch was already deleted on the remote |

## How to improve

1. Baton itself: make the stale-plan check ignore `~` line suffixes and bare ref names, so refiners do not need a second pass.
2. Baton itself: let a plan task that changes no code report the branch tip as its sha.
3. Baton itself: stop `merge-pr` from reporting a failed remote branch delete when the ref is already gone.
4. Planning practice: keep irreversible operations such as deleting remote refs out of a pull request's plan; file them as a separate step for the maintainer.
